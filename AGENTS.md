# AGENTS.md

Инструкции для ИИ-агентов, работающих в этом репозитории.

## Что это за проект

<!-- ЗАПОЛНИТЬ: что за сайт, для кого, ключевые особенности — 1–3 предложения. -->

- **Astro 7**, статическая сборка, Node >= 22.12.0, npm
- **SCSS** (`sass-embedded`) + каскадные слои, без Tailwind и других CSS-фреймворков
- **Чистый JS.** TypeScript в проекте не используется: пишем `.js` и `.astro`, `.ts` не создавать. `tsconfig.json` лежит только для подсказок в редакторе
- **Prettier** — единственный форматтер; окончания строк LF зафиксированы в `.gitattributes`

Не добавлять без явной просьбы: TypeScript, тесты, линтеры, Tailwind и другие UI-фреймворки, JS-фреймворки (React/Vue/Svelte), SEO-интеграции (sitemap, robots.txt), аналитику.

## Команды

```bash
npm run dev            # дев-сервер, порт 4321
npm run dev -- --host  # то же + доступ по локальной сети
npm run build          # сборка в dist/
npm run preview        # просмотр собранного dist/
npm run format         # prettier --write .
npm run format:check   # prettier --check . (должно быть чисто перед сдачей работы)
npm run astro -- <cmd> # прямой доступ к CLI Astro
```

После правок конфига, стилей или страниц: `npm run build` (убедиться, что собирается) и `npm run format:check` (убедиться, что формат в порядке).

## Структура

- `src/pages/` — страницы: `index.astro` (главная), `404.astro` (собирается в `404.html`)
- `src/layouts/Layout.astro` — `<html>`, head, пропсы `title`/`description`/`image`, og-теги, `canonical`, подключение шрифта и `global.scss`. Страницы оборачивать в него, не дублировать head
- `src/components/` — `Header`, `Footer`, `ArtDirectedImage`
- `src/assets/` — картинки для обработки Astro (импортируются в код)
- `public/` — статика как есть (`favicon.svg`, `og-image.webp`)
- `src/styles/` — `global.scss` (точка входа) + partials `_layers`, `_reset`, `_custom-reset`, `_base`
- `src/styles/helpers/` — модули-хелперы: `_index.scss` (барель через `@forward`), `_media.scss` (брейкпоинты), `_mixins.scss` (миксины), `_functions.scss` (функция `fluid()` и приватная `_round()`). Подключаются автоматически, см. «Правила стилей»

## Правила стилей

**Хелперы подставляются автоматически.** В `astro.config.mjs` настроен `vite.css.preprocessorOptions.scss.additionalData`, который добавляет `@use "/src/styles/helpers/_index.scss" as *` в каждый SCSS-блок, компилируемый Vite. Поэтому в `<style lang="scss">` компонента и в `global.scss` не нужно писать `@use` для миксинов и переменных — они уже доступны:

```scss
.card {
  @include mobile-down {
    padding: 12px;
  }
}
```

Строка не подставляется в partials, которые подключаются через `@use` из `global.scss` (`_base.scss` и т.п.) — там нужен явный `@use './helpers/index' as *;`.

Новый модуль хелперов: создать `src/styles/helpers/_имя.scss`, добавить `@forward 'имя';` в `_index.scss`, а его собственные зависимости прописать `@use` внутри него самого. Порядок `@forward` в барели не делает переменные соседних модулей видимыми — например, `_mixins.scss` сам пишет `@use 'media' as *;`, иначе `$mobile` внутри миксина не определён. Всё, что отдаётся наружу (миксины, функции, переменные), в подключаемых файлах объявляется обычными `@mixin` / `@function` / `$var` — `@forward` их пробрасывает сам, дублировать `@forward` в `_index.scss` для переменных не нужно.

Есть `mobile-down` / `mobile-up` (граница `$mobile`), `hover` (только устройства с мышью), `visually-hidden`, `absolute-cover`; переменные `$laptop` (1440px), `$tablet` (1024px), `$mobile` (768px), `$mobile-s` (480px) — в `helpers/_media.scss`. Не вводить новые брейкпоинты и не писать `@media (max-width: ...)` руками — использовать миксины.

**Плавные значения — `fluid()`.** `fluid($min, $max, $screen-min: 390px, $screen-max: 1920px)` возвращает готовый `clamp()`, у которого на границах диапазона экранов ровно `$min` и `$max` — те значения, что нарисованы в макете, без подбора `vw` наугад:

```scss
.title {
  font-size: fluid(16px, 24px); // 16px при 390px → 24px при 1920px
  padding-inline: fluid(40px, 24px); // убывает: 40px → 24px
  gap: fluid(8px, 16px, 768px, 1440px); // свой диапазон экранов
}
```

Правила и крайние случаи:

- всё в одних единицах: либо `px`, либо `rem` — и значения, и экраны. Для `rem` экраны тоже в `rem` (`fluid(1rem, 2rem, 24rem, 120rem)`), потому что пересчёт опирается на корневые 16px
- безразмерный `0` допустим (`fluid(0, 2px)` — частый случай нулевого `letter-spacing`), он приводится к единицам соседа
- `$min == $max` → вернётся просто значение, без `clamp()` и `calc()`
- разный знак наклона не проблема: `fluid(40px, 24px)` даёт убывающую линию, границы `clamp()` при этом меняются местами
- `$screen-min > $screen-max` не ошибка — линия просто идёт в обратную сторону; смешанные единицы и равные границы экранов дают `@error` с понятным текстом
- `line-height` и другие безразмерные значения функция не принимает: множитель не во что пересчитывать без базы
- `vw` считается от ширины окна, а не от контейнера: в узкой колонке на широком экране значение будет «как на весь экран». Для типографики и отступов, масштабирующихся вместе с макетом, это то, что нужно; для «резиновости внутри блока» — нет
- дефолтный диапазон 390…1920 меняется в сигнатуре функции целиком под макет, а не аргументами в каждом вызове

Функция отдаёт `calc()` с округлением до 4 знаков (приватная `_round()`), поэтому в CSS уезжает компактное `clamp(16px, calc(13.9608px + 0.5229vw), 24px)`, а не строка на полэкрана.

**Слои.** Порядок объявлен один раз в `_layers.scss` (`@layer reset, base;`): правила из `reset` слабее, чем из `base`. Стили в `<style>` компонента идут **вне слоёв** и перебивают и reset, и base — если нужно переопределить базовый стиль, пиши его прямо в компоненте, специфичность выкручивать не нужно. Новый слой: добавить имя в строку объявления по возрастанию приоритета, завести partial и подключить его через `@use` в `global.scss`.

**Шрифт** — Roboto через конфиг (`fonts` в `astro.config.mjs`), в `Layout.astro` подключается компонентом `<Font cssVariable="--font-roboto" preload />` и применяется через `font-family: var(--font-roboto)`.

## Картинки

`getImage()`, `<Image>`, `<Picture>` принимают только **импортированные** картинки:

```astro
---
import img from '../assets/photo.jpg';
---
```

Строковый путь из `public/` они не принимают. `ArtDirectedImage.astro` — готовый компонент для разных пропорций на мобиле и десктопе (`<picture>` + `<source media>` + 2x), внутри файла шпаргалка по остальным случаям.
